Array Algorithms

Four things you'll be asked to do with an array over and over: find the biggest or smallest value, count how many values fit some rule, and put everything in order. Every one of them is just a loop with a little bit of bookkeeping in a variable.

The trick: assume the first element is the best one so far, then check every other element — only replace your answer when you find something better.

3Sorting: Bubble Sort

Walk through the array comparing each pair of neighbors; if they're in the wrong order, swap them. One full pass pushes the largest remaining value all the way to the end — repeat until nothing is left to sort.

comparing this pair just swapped locked into final position
In real code: you'd almost never hand-write bubble sort — you'd call Array.Sort(numbers); from Lesson 1 and let it pick a fast algorithm for you. Bubble sort is worth learning once anyway: it's the simplest possible sort to trace by hand, and "compare neighbors, swap if needed" shows up inside faster sorts too.

Why this matters

  • "Best so far" pattern: max/min both start by assuming the first element is the answer — starting at 0 (like a sum) would give the wrong answer for an array of all-negative numbers.
  • Counting vs. summing: summing adds the value every lap; counting adds 1 only when a condition is true. Mixing these up is a very common beginner bug.
  • Bubble sort is O(n²): for 6 elements that's up to 15 comparisons; for 1,000 elements it's about 500,000 — which is exactly why real code reaches for Array.Sort instead.
  • After bubble sort's k-th full pass, the last k elements are guaranteed to be in their final sorted position — that's why each pass can stop one element earlier than the last.
