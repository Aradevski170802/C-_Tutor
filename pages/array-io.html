Lesson 8

Reading & Printing Arrays

Two things you'll do with almost every array you ever write: get values into it from input, and get values out of it to show the user what happened. Neither one needs anything beyond a for loop and the basic types you already know.

1Reading a whole array from one line

Calling Console.ReadLine() five separate times to fill five slots works, but it's slow to type and easy to mess up. Instead, let the user type every value on one line, separated by spaces, and split it apart in code.

string[] parts
int[] numbers
Watch out: int.Parse() crashes with a FormatException if the text isn't actually a valid number — extra spaces, a stray letter, anything. int.TryParse() is the safer version: it returns true/false instead of crashing, which is worth switching to once you're comfortable with bool.

2Printing every element of an array

Console.Write prints without moving to a new line — perfect for building up one line of output element by element inside a loop. Console.WriteLine (with no arguments) moves to a new line once you're done.

3Printing a matrix (2D array)

The same idea, nested: the inner loop writes one row using Console.Write, and Console.WriteLine() only runs once the whole row is done — that's what moves the output down to the next line.

Why this matters

  • Split(' ') cuts a string apart wherever it finds a space, handing back a string[] — every value still needs converting with int.Parse before you can do math with it.
  • Write vs. WriteLine: mixing them up is how you get output that's either all jammed onto one line, or has a stray blank line after every single value.
  • A "\t" (tab) between values, like in the matrix example, keeps columns roughly aligned even when the numbers have different widths.
  • Reading and printing aren't graded on style, but readable output makes it far easier to spot a bug in whatever the rest of your program computed.
